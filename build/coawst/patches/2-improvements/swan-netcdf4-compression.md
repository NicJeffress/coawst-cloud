## In short

ROMS can write compressed NetCDF-4 files: build with `OUT_NETCDF4` (NetCDF-4/
HDF5 files instead of classic NetCDF) and `DEFLATE` (lossless compression of
each variable). SWAN, inside the same executable, ignored both options and
always wrote classic, uncompressed files. In a coupled run with SWAN output
every few minutes, SWAN's files were often the larger part of the output.

The patch passes the two options to SWAN's NetCDF writer: with both, SWAN
creates NetCDF-4 files and compresses every multi-dimensional variable
exactly as ROMS does (shuffle filter, deflate level 1). The values read back
are identical, since the compression is lossless, and the files are 2 to 4
times smaller. Without the options SWAN's files stay classic, as before.

| Change | What was missing | Effect |
|---|---|---|
| `netcdf4_compression` | SWAN's NetCDF writer did not see the cpp options of the case header, and always created classic, uncompressed files | with `OUT_NETCDF4` + `DEFLATE`: compressed NetCDF-4 files, values identical, 2-4x smaller; otherwise unchanged |

## Background: NetCDF-4 and compression

A classic NetCDF file stores every number in full, one after another. A
NetCDF-4 file is an HDF5 file underneath, and HDF5 can pass each variable
through filters on its way to disk:

- **shuffle** reorders the bytes of a block of numbers so that all first
  bytes come together, then all second bytes, and so on. Neighbouring
  values of a smooth field share their leading bytes, so this makes long
  runs of similar bytes;
- **deflate** (zlib, the algorithm of `gzip`) then compresses those runs.
  Level 1 is the fastest; higher levels gain little on model output.

Both are lossless: the numbers read back are bit for bit the numbers
written. NetCDF libraries decompress transparently, so programs that read
the files (Python `netCDF4`/`xarray`, MATLAB, `ncdump`) need no change.

ROMS does this when built with `OUT_NETCDF4` and `DEFLATE`
(`def_var.F`: `nf90_def_var_deflate(ncid, varid, shuffle=1, deflate=1,
level=1)`, with the levels from `ocean.in`). Fields with large uniform areas
(land, dry points, zero dissipation offshore) compress best.

## netcdf4_compression: the change

SWAN's NetCDF output is written by `agioncmd.ftn90`, a free-form Fortran 90
module that, unlike SWAN's `.ftn` files, did not include COAWST's cpp header,
so it never saw the case's options. The patch:

1. includes `swancpp.h` (ROMS's `cppdefs.h` with the case header), as SWAN's
   other COAWST-aware sources do:

   ```fortran
   +#include "swancpp.h"
          module agioncmd
   ```

2. creates NetCDF-4 files when `OUT_NETCDF4` is defined:

   ```fortran
   +#if defined OUT_NETCDF4
   +            ! compressed NetCDF-4/HDF5 file, as ROMS (swan-netcdf4-compression)
   +            call nccheck ( nf90_create( ncfile, IOR(NF90_NOCLOBBER, NF90_NETCDF4), ncid) )
   +#else
                call nccheck ( nf90_create( ncfile, NF90_NOCLOBBER + NF90_64BIT_OFFSET, ncid) )
   +#endif
   ```

3. adds a routine that compresses one variable, empty unless both options
   are defined:

   ```fortran
   +        subroutine agnc_compress( ncid, varid )
   +            integer,              intent(in)                    :: ncid, varid
   +#if defined OUT_NETCDF4 && defined DEFLATE
   +            call nccheck ( nf90_def_var_deflate( ncid, varid, 1, 1, 1 ) )
   +#endif
   +        end subroutine agnc_compress
   ```

4. calls it after each of the 16 `nf90_def_var` statements that define a
   multi-dimensional variable: the quantities of `BLOCK` and `TABLE` output,
   the curvilinear `x`, `y` coordinates, and the spectral variables of
   `SPECOUT`:

   ```fortran
                call nccheck ( nf90_def_var(ncid, trecord%name, trecord%nctype, (/ ... /), evarid) )
   +            call agnc_compress( ncid, evarid )
   ```

   The 1-D axes and `time` stay uncompressed (they are small, and readers
   often scan them). The generator checks that it found exactly 16 such
   statements, so a change in SWAN's source cannot silently leave one out.

Chunking is the NetCDF library's default (one record of each field per
chunk), which suits fields written one time at a time.

One trap, noted in the source: cpp replaces option names wherever they
appear, also inside Fortran comments, so this file's comments must not name
cpp options. The case header was checked for macros that would rewrite
SWAN code (none in the cases tested).

## How the test works

`tests/improvements/swan-netcdf4-compression/run.sh`
([README](../../../../tests/improvements/swan-netcdf4-compression/README.md))
runs COAWST's coupled Inlet_test for 1 h with SWAN output every 10 min, all
as `.nc`: six `BLOCK` fields on the computational grid (HSIGN, DIR, TM01,
VEL, DISSIP, QB), a `TABLE` at 9 points and `SPECOUT` 2-D spectra at the same
points. Three builds:

| Run | Build | SWAN files expected |
|---|---|---|
| `before` | without the patch, `+OUT_NETCDF4 +DEFLATE` | classic (ROMS compressed, SWAN not) |
| `after-classic` | with the patch, no options | classic |
| `after` | with the patch, `+OUT_NETCDF4 +DEFLATE` | NetCDF-4, compressed |

It checks the file formats and filters, that every variable of every SWAN
file (data, missing points, attributes) is identical in the three runs, that
the ROMS history is identical between `before` and `after`, and reports the
sizes.

## Engine test results

Run 2026-10-31 on the control VM (ROMS 1x1 + 1 SWAN, 1 h). PASS.

```
ok  format before: SWAN files NETCDF3_64BIT_OFFSET
ok  format after-classic: SWAN files NETCDF3_64BIT_OFFSET
ok  format after: SWAN files NETCDF4
ok  filters after: 30 multi-dimensional variables with shuffle + deflate, 14 1-D variables plain
ok  ROMS format before: NETCDF4
ok  ROMS format after: NETCDF4
ok  SWAN values: 44 variables in 8 files identical in all three runs
ok  ROMS values: history: 211 variables, 0 differ
ok  size: SWAN files 1.58 MB (before) -> 0.78 MB (after), 2.0x smaller
```

| File | classic | compressed |
|---|---|---|
| `b_hsign.nc` (Hs) | 204 kB | 113 kB |
| `b_dir.nc`, `b_tm01.nc` | 204 kB | 103 kB |
| `b_dissip.nc` (dissipation) | 204 kB | 121 kB |
| `b_qb.nc` (fraction of breaking waves, mostly 0) | 204 kB | 28 kB |
| `b_vel.nc` (two components) | 360 kB | 184 kB |
| `spec.nc` (2-D spectra, 9 points) | 198 kB | 97 kB |
| `pts.nc` (table, 9 points) | 6 kB | 30 kB |

Run time is unchanged within noise (67-69 s for all three runs). Very small
files grow: an HDF5 file has a minimum size of a few tens of kB, so a
9-point table went from 6 to 30 kB.

Earlier result (2026-10-29), idealized fringing reef (2 ROMS + 2 SWAN
processes, 30 min, `BLOCK` output every 2 min plus `TABLE` and `SPECOUT`):
every variable bit-identical to classic output, SWAN files 4.0x smaller
(20.2 -> 5.0 MB), about 1 ms more per file write. Larger grids with land
compress better than Inlet_test.

## Who is affected

Builds with `OUT_NETCDF4` and `DEFLATE`: SWAN's `.nc` files are now NetCDF-4
and compressed, like ROMS's. Readers that handle NetCDF-4 (all current
NetCDF libraries) need no change; very old tools that read only classic
NetCDF (NetCDF 3 libraries) cannot open them. Builds without the options are
unchanged.
